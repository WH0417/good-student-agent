# 好学生 Agent 工程版本说明

版本：0.1.0  
日期：2026 年 11 月 18 日

本轮完成第一个可运行的文本资料版本。产品由本地 Python CLI 和主技能构成，已经能够将课程文本、明确重点、练习与学习进度持久化，并按所选模式导出复习资料。详细讲解、语义总结和变式题由使用主技能的 Agent 根据原材料完成，程序负责来源校验、规则执行与数据留存。

## 1 已实现的流程

1. 创建独立科目并选择高分或速通，保存卷面满分和及格目标。
2. 导入课堂逐字稿、豆包纪要、文字课件和题目，原件按内容哈希留存；重复导入不重复累计重点。
3. 识别有具体对象的教师明确重点和明确会考表述，保留原话、来源和实际位置；疑点进入候选。
4. 接收用户指定重点，或由用户确认候选；来源始终标为用户指定。
5. 记录老师后续明确取消考试范围的证据，使原教师结论失效，同时保留用户自己的复习指定。
6. 分段读取原文，保存 Agent 撰写的课次总结；默认原文预览不会被包装成已经完成的知识总结。
7. 生成结构性知识目录、文字提纲、Mermaid 导图和双模式任务顺序，允许显式关联前置知识。
8. 整理题目与参考答案，保留稳定题目编号；保存有可核对来源的 AI 生成变式。
9. 记录实际作答、提示与答案查看情况；独立通过与看过答案后的复述分开。
10. 恢复指定课程的学习状态，生成重点、复习资料、练习、导图及清单快照。

## 2 复用方式与问题修正

从固定提交的学习项目中复制了 `text`、`extract`、`chapters`、`index`、`questions` 及其包声明，并保留 MIT 版权和许可证。原始参考仓库未修改。

复用边界位于 `good_student/vendor/coach`，产品不调用上游 CLI、不使用其最后课程指针，也不调用其宽松数值判分。我们自己的适配层负责：

- 以内容和来源生成稳定题目编号，新增文件不再改变旧错题的关联。
- 精确数字默认精确比较，近似容差必须显式提供；`2.4` 不被当作精确答案 `2`。
- 明确课程编号、重点证据和用户模式，避免按真题频率自动增加正式重点。
- 多科数据隔离、同科写入串行和权威状态原子替换。

## 4 数据保存约定

本版本以 `data/courses/<course_id>/state.json` 为单科权威状态。来源、课次、重点、知识节点、题目与作答在一次课程事务内更新，避免多个 JSON 文件分步更新产生不一致。原件放在同科 `sources` 下，导出放在同科 `exports` 下。

这是对设计中多文件结构的简化实现：数据语义保持一致，阅读视图通过导出生成。读取到损坏结构时保留原始文件并明确报错，不自动清空学习记录。写入锁由操作系统释放，不通过删除锁文件猜测其他进程是否仍在使用。

所有课程操作显式携带课程编号。技能入口额外要求明确数据目录，防止将资料写入其他项目；不会写全局课程指针。

技能格式校验已通过。独立前向检查按真实操作顺序完成“纪要导入—用户指定—总结保存—速通导出—切换高分—新进程恢复”，发现的纪要候选、来源位置和导出路径问题已修正并补充验证。

独立技能包包括业务代码和上游许可证，可在没有 `references` 目录的临时项目运行。最新输出与校验和记录在 `dist/latest.json`。

## 6 当前边界

- 原始录音目前归档并标为待转写，没有内置已配置的自动转写引擎。使用豆包或其他工具已有逐字稿可直接开展后续流程。
- 核心无需第三方依赖；PDF 接口已接可选解析器，但当前运行环境没有安装相关库，因此没有将真实 PDF 文本与图像能力计为本轮验证通过。
- 知识目录是基于标题、原文和重点证据的结构索引。精华总结、概念理解、公式说明和变式题正确性需要 Agent 阅读材料后完成；程序不会把规则提取冒充语义理解。
- 当前没有扫描件 OCR、移动录音界面、教师风格分析或课程总评计算。
- 未使用用户真实课程做学习效果评估，不把测试通过或模拟作答解释为真实考试分数保证。

后续优先用一门真实课程完成资料导入和知识总结验证，再接入可配置的录音转写与扫描页处理。完整首版仍以已确认设计中的 R01 至 R08 和 A01 至 A19 为验收依据，本次不声明全部完成。
